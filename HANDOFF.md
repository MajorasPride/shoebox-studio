# Shoebox Studio: handoff notes

_Last updated: Nov 13, 2026 (v1.6c live on `main`; VHS spot (T020), picture examples (T021), Art Swap (T022), 3D polish (T029), Supply Store (T032), Make it 3D (T033), Creator Mode (T034) and the Medium engine with the file split (T024) built on `dev` only, waiting for the owner's look; rollback copy of v1.5.2 in `/v1.5.2/`)_

## Vision
- Shoebox Studio is the **one video game that holds everything**: you make game assets, levels, stories and music, and you make whole games, all inside it. The owner's other tools plug in as stations. Their working copies stay with Claude, and the game gets big updates when the owner says so.
- Models (from the planning chat): LittleBigPlanet (Play, Create, Share) and Animal Crossing (townsfolk you craft, real clock, seasons, daily chores, a museum for crafts). Little Town is the hub, and later **any building can hold a level you made**. Dioramas ("fill a shoebox scene") can turn into playable levels. All original designs and names: no Nintendo or LBP characters, and trademarked toy names stay generic.

## How updates work (owner's rule, Nov 12, 2026)
- Small updates happen **on our end** in working copies: the private Claude artifacts, plus the `dev` branch of this repo.
- The public game (`main` branch = the live website) only gets **big, fleshed-out updates**, and only when the owner says go.
- Staged work waits on `dev`. It's in the repo but not on the website.
- **Nothing goes live without the owner's final look.** Before every big update, give the owner a private preview of the whole `dev` version to play. Push to `main` only after they say go.
- **One-time exception (Nov 13, 2026):** the owner chose to put this first update (v1.4) live right away, without the preview step ("push everything we talked about now to the website, I wanna see how it goes"). The normal rule above still applies to every future update.
- **Second exception (Nov 13, 2026):** the owner asked for v1.6a, v1.6b and v1.6c to be built and put live the same night ("build everything and go live tonight"), each tested on `dev` first, with a rollback copy of the live version. Done by Opus in Claude Code on the laptop. The preview-first rule is back in force from the next update.

## Medium engine, real desk and the file split (built Nov 13, 2026 by Fable, ticket T024; on `dev` only, not live)
Three things in one order: the game is split into files, every art medium is a recipe with paint that really mixes, and the School Desk has real supplies and a painting kit.

### The files (read this first: the code is no longer in index.html)
`index.html` now holds only the markup, the CSS and the script tags. The code is in plain script files, loaded in this order, with no build step and no bundler:
1. `lib/spectral.js`, `lib/perfect-freehand.js` (both `async`: the game runs without them until they arrive; mixing falls back to plain blending and the pen to plain lines).
2. `core.js`: the loop (`frame`), saves (`LS`), helpers, sound, Toy Box data, screens (`go`, `showScr`), Settings, input, the game clock, the room engine (walking, stations, `drawLobby`) and the content pack loader (T034).
3. `mediums.js`: the medium engine (`MEDIUMS`, grain painters, mixing, `medSeg`), paper stocks, medium tags.
4. `desk.js`: the School Desk (pieces, cut, fold, stick, draw), the real desk supplies and painting kit, tabs and chips, flip paper.
5. `classes.js`: Art Class (`CLASS`) and picture examples (`EXAMPLES`).
6. `town.js`: Make a Level, Little Town (Build, Walk), companions, HUD layer, living town, Handy Notebook.
7. `stations.js`: the rooms (`STATIONS`, `HOUSE`, `SHOPS`, `STATION_DRAW`), Pixel UI Kit, Toy Box library, projector, VHS, console save, 3D hooks, **start-up**, then Art Swap. It ends with `READY=1`.
- `r3d.js` is unchanged and still loads only when 3D opens.
- All files share one global scope, like the old single script. A `function` can be called from any file once the page has loaded. A `const` or `let` that is **used while a file is loading** must be in an earlier file (or earlier in the same file). When older notes below say "in index.html", search all the `.js` files for the comment title instead.
- **READY** (core.js): taps, keys and resizes do nothing until the last file has loaded, so nothing runs half-loaded. Keep `READY=1` the last line of `stations.js`.
- The start-up lines (`resize(); loadDesk(); ... requestAnimationFrame(frame)`) sit in `stations.js` just before the Art Swap block, the same place in the order as before the split.
- The split was committed on its own first ("Split index.html into ...") with no change in behaviour, then the engine on top.

### The medium engine (`mediums.js`)
- **`MEDIUMS`** replaces the `MEDIA` list (`MEDIA` is kept as another name for the same list, so old code, old saves and `p.med` tags still work). One recipe per medium: `em`, `name`, `w` (width), `a` (opacity), `grain` (texture painter), `fixed` / `lift` (colour rules), `wet` (0 to 1: how much it smears), `mix` (`'spectral'` = wet paint that mixes, `'stack'` = dry, lies on top), `paper` (how each `STOCKS` paper reacts: `spread`, `soak`, `tooth`), `press` (S Pen pressure curve), `sound` (a `RUBS` name in core.js), `steps` (three class steps, shown in the Art box under "How to use it"), and the looks `halo`, `bloom`, `shine`, `aura`, `sparkle`, `glows`, `glitters`.
- **To add a medium:** one new entry in `MEDIUMS`. If it needs its own texture, add a painter to `GRAIN_PAINT` (a function that draws a 512 px grey tile) and name it in `grain`. Nothing else: the Art box, the Toy Box medium filter, the notebook and the tags all read the list.
- **Mixing** (`blendOn`, `strokeStart`, `blendStep`, `smix`): each stroke carries `B` (what is on the tip). For a `'spectral'` medium every step looks at the paper just ahead of the tip (`underAt`), picks some of that paint up (`B.pick`, `B.amt`, it wears off along the stroke: that is the smear) and lays down the spectral.js mix. Bare paper and a paler wash of the same colour do not count as paint (`samePaint`), so going over your own wash builds up as before. `smix(a,b,t)` mixes two `[r,g,b]` colours like paint and caches results.
- **Settings > Paint mixes** (`SET.blend`, on unless turned off). Off = every medium draws exactly as in v1.6b (checked pixel for pixel). `medSeg(c,m,col,pts,k,stock,B)`: without `B` it also draws the old way.
- **Paper feel** (only with Paint mixes on, except watercolour on watercolour paper, which is the old v1.6b reaction and always shows): rough papers (cardboard, kraft) take dry mediums more lightly, thirsty papers spread paint.
- **S Pen** (`drawStart`, `drawFree`, `penFlush` in desk.js): only for `pointerType === 'pen'`. perfect-freehand smooths the points and the pressure; `pressK` turns pressure into width from the recipe. Finger and mouse strokes are unchanged.
- **Grain masks** are now made the first time a grain medium is used (`grainInit`, `grainMask`), not at start-up.
- **Yarn and felt textures:** `GRAIN_PAINT.felt`, `.knit`, `.stitched`, `.burlap` are copied from Mythic Forge (`myth-forge/materials.js`). No medium uses them yet: they are ready for the Clay Table / yarn ideas (T041). To try one, set `grain:'felt'` on any recipe.

### Real desk supplies and the painting kit (`desk.js`, "REAL DESK SUPPLIES AND THE PAINTING KIT")
- **Settings > Drawing tools** (`SET.tools`): **Real desk** (new players) or **Quick tools** (old saves keep this; today's bottom toolbar only). Both draw with the same recipes, and the Art box chip works in both (it is how you reach charcoal, chalk, oil pastels and the gel, glitter and glow pens).
- Real desk: a **crayon box** (12 crayons) and a **pencil cup** (a pencil and 12 coloured pencils) above the paper, a **marker tray** (12 markers) below it, and to the right the **palette**, a **brush rest** (round, flat and fine brush, palette knife) and a **water cup**. The Draw tab's **Paints** chip slides the view to the painting kit and back.
- Tap a supply to pick it up (if they are too close together on the screen, the first tap zooms in). It shows in the Player Hand and the Pencil tool draws with it. Tap the bare desk with the Pencil tool to put it down; it stays there. Picking up another one puts the first back in its box.
- **Palette** (`paletteDlg`): pick two paints, slide to mix (spectral.js), pick poster paint or watercolour, "Load the brush". **Dirty brush:** loading a new colour without rinsing, or dragging through wet paint, leaves old paint on the brush (`DSV.dirt`) that tints every stroke until you tap the **water cup** (`dsRinse`); the water slowly takes on the colours.
- Brush shapes are `DS_TIPS` (width factor, flat, knife). The palette knife always uses poster paint.
- Save: `craftloft_desksupplies` = `{out:{id:[x,y,rot]}, held, pal:{a,b,t,paint}, bcol, dirt, cup}`. To add a supply: one more entry in `DS_LIST`.
- The default School Desk zoom is a little further out with the Real desk on, so the supplies above and below the paper show on a phone.

### Choices made
- **Paint mixes is on for everyone**, old saves too (it is the point of the update); Settings turns it off.
- **Blending is done per brush step, not per pixel**, on the normal 2D canvas. It is fast on a phone, so no GPU version was needed.
- **MEDIA stays as a second name** for MEDIUMS rather than renaming every use.
- **The room engine's functions moved to core.js** (as the order asked), but the room data and `let RM` stay in stations.js because they need the station lists while loading.
- **Supplies that are not crayons, pencils or markers** stay in the Art box rather than getting desk objects (the order named three holders and the painting kit).

## Creator Mode (built Nov 13, 2026 by Opus, ticket T034; on `dev` only, not live)
The owner's own page for adding new default things to the game for every new player. Code: `creator.html` (the whole page) and the "CONTENT PACK (T034)" block at the end of the main script in index.html, plus small hooks marked T034.
1. **creator.html** is in the repo root and is not linked from the game. Sections: **Pieces** (every piece in this browser's Toy Box, his own first, plus pieces from an imported Shoebox file: a Toy Box export, an art pack or a content pack), **Make a new thing**, **The content pack**. "Open the game to make a piece" opens the game in a frame on the same page: he makes the piece at the School Desk, Pixel UI Kit or Toy Box, saves it to the Toy Box, taps Back to the Creator, and it is in the list (same site, same browser storage).
2. **What a thing can be:** 🧸 Item (every Toy Box: behaviour, what it does in town, walk through, medium tag, price), 🏡 Town piece (the same, plus "stand it in the showcase town" at a spot), 🏪 Building (in Little Town with a door and a room: a Shop Door and a counter with his name and note; width in town), 🛒 Shop stock (on the Supply Store shelves or on one of his buildings' counters, with a price and medium tag; not in the Toy Box), 📘 Lesson (Art Class branch or a new "⭐ New lessons" branch, a short line, a finished picture, and steps: text, which School Desk tab opens, an optional picture each).
3. **Export / import:** Export content pack downloads `content-pack.json` (`{format:'shoebox-content-pack', version:1, made, entries:[{key, kind, name, toy, ...}]}`; a Copy box shows it too). Import pack loads one back to keep editing. The pack being worked on is kept in this browser as he goes (`craftloft_creator_draft`; imported pieces `craftloft_creator_imported`).
4. **Try it in the game** saves the pack to `craftloft_creator_try` and opens `index.html?pack=try` in the frame: the game uses that pack instead of the repo's one, in this browser only. It adds the pack things to this browser's own game save (they are refreshed or taken out again by whichever pack loads next).
5. **How the game loads it:** at start the game reads `content/default-pack.json` (a quick synchronous read, so buildings, lessons and the showcase town are set before anything draws; no file = the game exactly as before). `cpData()` checks it. Items and town pieces go into the Toy Box as `cp_<key>` (tags "content pack", "item" or "town piece", and the medium); `price` is kept on the toy for T027. Town pieces he placed go into the showcase town (new saves and Reset to showcase town only; old towns never move). Buildings are `BLD['cp_<key>']` with a room `SHOPS['cp_<key>']`, so taps, walking in, Build mode dragging, the free-spot placement for old towns, Quick resume and Retro 3D all work through the T032 loops; `BLDDRAW` draws them from the picture. Shop stock lists on the shelves or counter (`cpShelf`): "Buying arrives with the shops update". Lessons go into `CLASS` as `cp_<key>` and their pictures into `EXAMPLES`.
6. **Order:** the player's own stuff, then the content pack, then the code-made defaults. The player's own pieces, towns and saves are never changed. A pack piece he (a player) deletes from the Toy Box stays deleted (`craftloft_cpack_gone`). When the pack changes a piece, the player's copy is refreshed; when a piece leaves the pack, it leaves the Toy Box.
7. **Art Swap:** every pack thing gets a slot automatically (group "Content pack" for items, town pieces and shop stock; "Buildings in town" for buildings; the room and stations through the T032 loops; lesson pictures through `EXAMPLES`). A player's own swap wins over the pack art.
8. **Publishing (his steps):** in creator.html tap Export content pack, put `content-pack.json` in the Shoebox Drive folder and write "content pack ready" in the Inbox. A small Sonnet order then commits it to `dev` as `content/default-pack.json` (and it goes live with the next big update, after his look).
9. **Not secret:** on a free GitHub Pages site anyone can open `creator.html` if they guess the address. It only changes that visitor's own browser. Only a pack committed to the repo reaches players.

## Make it 3D menu (built Nov 13, 2026 by Opus, ticket T033; on `dev` only, not live)
Code: `M3D` and `m3dDlg` in index.html (search "Make it 3D (T033)"); `pieceMesh`, `backCanvas` and `puffyGeom` in r3d.js (search "T033").
1. **Standee by default.** Every drawing already stands up in Retro 3D as a thick cardboard standee (T029's `thickCut`), with no extra steps. No `toy.m3d` key = Standee.
2. **The menu** (Toy Box > tap a piece > 🧊 Make it 3D) has five choices, with the spinning preview:
   - 🪧 **Standee** (default, no key).
   - 🫓 **Puff** (`toy.m3d = 'clay'`): inflated like clay or a pillow, round in the middle, thin at the edges. Our own code after Monster Mash's inflate idea (no Monster Mash or Triangle code copied): distance to the edge gives a round cross-section, the rim is pinned at zero so the two halves meet with no gap, then 6 smoothing passes turn the ridge along long shapes into a soft pillow. The picture is grown a few pixels past its edge so the seam has no pinholes.
   - 📦 **Fold** (`'paper'`): the v1.6c papercraft, unchanged.
   - 🔄 **Two sides** (`'two'`): the drawing in front and the back of the paper behind, on a cardboard edge. The back comes from Flip paper (`toy.sheet.back`, saved when a two-sided sheet goes to the Toy Box). A one-sided piece shows a "Back:" picker: any other Toy Box piece (`toy.m3dBack` = its id, fitted into the front's shape) or plain cardboard. The back is flipped so it reads the right way round from behind.
   - 🐉 **Mythic Forge** (greyed, "coming"): for the Forge station later. Both apps use three.js r160, so a Mythic Forge `.glb` can load with three.js `GLTFLoader` (`examples/jsm/loaders/GLTFLoader.js`, MIT; add it to lib/ and CREDITS.md when that order comes) into `pieceMesh` as one more style.
3. The ids `'paper'` and `'clay'` are kept from v1.6c, so old saves and the T021 example pieces keep their look. Saving Standee removes `m3d` and `m3dBack`. Saving calls `R3.forget(id)` so a changed piece redraws in 3D.
4. Where it shows: pieces placed in Little Town (2D stays the same). Rooms show stations, not Toy Box pieces, so there is nothing there to change yet; any later order that places pieces in rooms should build them with `pieceMesh(toy)` and they will follow the menu.

## Retro 3D polish (built Nov 13, 2026 by Opus, ticket T029; on `dev` only, not live)
Fixes from the owner's 3D testing of the T020-T022 preview. Code: `r3d.js` (3D), a small `faceStep` block next to `fixItem` and the Turn button in `updItemBar` in index.html, `lib/three-mesh-bvh.module.min.js` (new, MIT).
1. **Facing rule.** Only things that move turn to face you in 3D: pieces with the Drives behavior (`act: 'vehicle'`, the cars). Everything else keeps a fixed facing. (The hero, pet and Player Hand are not drawn in 3D yet; when they are, they follow the moving rule.)
2. **Facing is set when placed.** `faceStep(it)` gives 8 steps (0 front = toward you in 2D, 2 right, 4 back, 6 left). It uses `it.rot` when set; otherwise the piece faces the nearest road piece within 160, else the front. Build mode in Little Town has a **🔄 Turn** button on the item bar (not for cars or road pieces): each tap turns it one step, says which way it faces, and saves `it.rot` with the piece. The selected piece shows a small red arrow at its feet for its 3D facing. Old towns load with the default facing (no `rot` key).
3. **Cardboard thickness** (`thickCut`, `edgeGeom`). Stationary cutouts (town pieces and every studio and house station, projector, VHS shelf, fridge and Art Swap included) get a real edge: the drawing's shape is traced on a 72-cell grid and an edge is built along it (chunky, retro), with the drawing on the front and, a little darker, on the back. Edge 8 (wall stations 4). Cars stay flat turning cutouts. Papercraft and Puffy clay are unchanged.
4. **Signs** (`signBox`). Names are small cardboard plaques, not floating labels. A station's plaque stands on the top edge of its own front, sized to the solid part of the drawing (75%, 56 to 112 wide), kept inside the room and under the wall top, a little in front of the station so it is never inside a wall. Thin bits (a flagpole) don't lift it. Buildings get a plaque on top of the front, sized to the building.
5. **Walls** (`solidBVH`, `collideBVH`). Walls, buildings, stations and blocking pieces become one collision mesh with a BVH (three-mesh-bvh). The camera stays 22 away from them (`CR`), checked at knee and eye height. Doors keep the old open/closed box check and cars keep the round check. Pieces set to "Walk through" do not block.
- Choices made: the edge is traced from the drawing rather than made with ExtrudeGeometry, because drawn pieces have holes and odd outlines that a three.js Shape would need a full outline tracer for; the traced edge uses the same three.js and matches the chunky retro look. ## How the new parts work (for the next builder)
Since T024 the code is in `core.js`, `mediums.js`, `desk.js`, `classes.js`, `town.js` and `stations.js` (see the T024 section at the top). Search those files for the comment titles below.
- **Rooms.** The lobby code now runs any room. `RM` is the room you are in: `LOB` (the studio) or `HOUSE`. Each room has a size, a station list (`stn`) and a background function (`bg`). The lobby's stations are still the `STATIONS` list. To add a station: one line in the room's list and one draw function in `STATION_DRAW`. A station does one thing: `go:'screen'`, `act:()=>...`, or `soon:1`.
- **Built-in tools ("BUILT-IN TOOLS" comment).** `TOOLS` lists each tool's folder. `openTool('shelf')` or `openTool('bbd')` shows the tool full screen in a frame, with a bar on top: a "Back to the studio / house" button, the tool's name, and a small ↗ link that opens the tool on its own page. The phone's Back button also closes it. The studio's music goes quiet and the game loop pauses while a tool is open. Closing removes the frame, so the tool's sound stops.
- **Saves.** Each tool saves under its own keys in the same browser storage (`storyshelf_v1`, `ds_*`), so nothing clashes with `craftloft_*`.
- **The house in town ("The player's house stands in Little Town" comment).** Its place is saved inside the town save as `TOWN.house`. Old towns get one added at a default spot the first time they load. Build mode: tap it to go in, drag it to move it. Walk mode: tap it, the hero walks to the door and goes in. It blocks walking like other pieces. The front door inside puts the hero back at the house door in walk mode.
- **The house room.** `HOUSE` and `drawHouseRoom`. It's drawn like a shoebox diorama with the roof on top. Places left open on purpose: the dotted shapes on the Display Shelf, the dotted ovals next to the pet bed, and the taped decoration spot.
- **Beat Bop Doodle's in-game copy** has no manifest and no service worker. Reason: it runs inside the game in a frame, and a service worker in a subfolder could keep serving an old copy after a big update. The stand-alone Beat Bop Doodle site keeps its own.
- **Tests run:** Playwright at phone (412×860) and PC (1280×800) size, from a v1.3 save: walked to the bookshelf, opened and closed Story Shelf (button and phone Back), entered the house from town in build and walk mode, opened and closed Beat Bop Doodle from the console, left by the front door, dragged the house, checked every other screen still opens. No page errors.
